# ISMS / fail-safe 改善ロードマップ

このプロジェクトでは、ISO/IEC 27001の正式な認証・準拠そのものではなく、ISMSを意識した安全運用に近づけることを目的に、段階的な改善を進めます。

## 今後の改善課題

- 監査ログを作る
- 重要操作の確認を強くする（利用者削除・機器削除・有料サービス削除の対象名入力確認、権限変更の変更前後表示、請求書押印のチェック確認を追加）
- 管理者・センター長権限を見える化する（利用者管理画面に権限別人数カードを追加）
- バックアップ・復旧手順を書く（暫定手順書を追加済み。DB提供事業者・契約プラン・保管場所などの確定と定期訓練は継続課題）
- 個人情報の表示範囲をさらに絞る
- エラー時の案内を統一する

## 今回の着手状況

監査ログの土台を追加しました。利用者・管理者による主要操作について、実行者、権限、対象、内容、日時を記録し、管理者が後から確認できるようにしています。監査ログの記録に失敗しても本体操作は継続する設計です。今回、利用者管理画面で権限別人数を表示し、権限変更の変更前後表示と監査ログ記録の案内、利用者削除時の氏名入力確認を追加しました。さらに、請求書押印の確認Dialogと再押印防止、機器・有料サービス削除の対象名入力確認を追加しました。

バックアップ・復旧の暫定手順書を追加しました。現在確認できるNext.js / Vercel / Prisma / PostgreSQL構成、pg_dump・pg_restoreによる復旧確認、件数確認SQL、Preview確認、本番切替、復旧記録、3か月ごとの復旧訓練を整理しています。RPO 24時間、RTO 8時間、1日1回以上の自動バックアップ、35日以上の保存期間は暫定目標として記載し、未確定事項は今後の運用課題として残しています。
