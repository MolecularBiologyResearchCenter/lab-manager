# エラー対応・障害調査ガイド

## 利用者向けエラー表示の原則

エラー画面には、利用者が理解できる日本語の「エラー」、次に取る行動を示す「次の操作」、問い合わせに必要な「問い合わせ番号」をこの順で表示します。内部のDB接続情報、環境変数、ファイルパス、スタックトレースは表示しません。重要な処理は原因が不明な場合も安全側に停止します。

## APIエラーコード

| コード | 意味 |
| --- | --- |
| `AUTH_REQUIRED` | ログインが必要 |
| `FORBIDDEN` | 権限がない |
| `NOT_FOUND` | 対象が存在しない |
| `INVALID_REQUEST` | 入力内容が不正 |
| `CONFLICT` | 現在の状態では処理できない |
| `CONFIGURATION_ERROR` | サーバー設定が未完了 |
| `INTERNAL_ERROR` | サーバー内部で予期しないエラー |

APIエラーは`error`、`code`、`guidance`、`requestId`を返し、レスポンスには`Cache-Control: no-store`と`X-Request-ID`を付けます。成功レスポンスにも同じ問い合わせ番号ヘッダーを付けます。

## 問い合わせ番号の使い方

利用者は画面に表示された問い合わせ番号を控えて、発生日時・画面名・操作内容と一緒に管理者へ伝えます。パスワード、再設定トークン、電子印画像、その他の個人情報や秘密情報を問い合わせに添付・送信しないでください。

## Vercel Function Logsで調査する手順

1. Vercelの対象プロジェクトを開きます。
2. `Logs`または`Functions`のログ画面を開きます。
3. 問い合わせ番号を検索します。サーバー側の500エラーは`[問い合わせ番号]`付きで記録されます。
4. 発生時刻、対象API、エラーの概要を確認します。秘密情報や個人情報をログへ追加しないでください。
5. 利用者には内部エラーの詳細を返さず、問い合わせ番号と安全な次の操作だけを案内します。

## 監査ログとの照合

問い合わせ番号の発生時刻を手掛かりに、管理者の「監査ログ」で実行者、操作、対象、内容を確認します。署名付きPDF取得などの重要操作は、請求書ID・請求書番号・操作日時を突き合わせ、利用者・権限・対象状態が一致していることを確認します。

## 障害時の安全側停止

認証、権限、請求書の押印状態、入力内容を確認できない場合は処理を実行しません。署名処理に失敗した場合も署名なしPDFを自動保存せず、利用者へ再試行または管理者への問い合わせを案内します。
